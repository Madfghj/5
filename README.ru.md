# OpenCalendar.space · онлайн-этап 0.2.1

Мобильный календарь для групп. Первая проверенная версия сохранена отдельно в OpenCalendar-v0.1-source.zip; эта папка содержит онлайн-приложение с облачным API и базой D1.

Работают группы и приглашения, события с 08:00 до 20:00 с шагом 30 минут, ответы «Да / Пока не знаю / Нет», имена участников рядом с ответами, регистрация и вход по почте, гостевой доступ и четыре языка. При первом запуске интерфейс английский: сначала предлагается выбрать язык, затем зарегистрироваться.

Google, Apple, Microsoft и Telegram подключаются через настоящий OAuth/OIDC, когда настроены ключи приложения. До настройки соответствующая кнопка недоступна. WhatsApp и Signal добавляются как необязательные контактные ссылки; они не выдаются за проверенные способы входа. Адрес почты в текущей версии не подтверждается письмом, восстановление пароля по почте пока не подключено.

## Запуск для разработки

Нужны Node.js 24+ и pnpm 11.25.0:

```sh
pnpm install --frozen-lockfile
pnpm run db:migrate
pnpm run dev
```

Откройте http://127.0.0.1:5174. API работает на порту 8788; локальные данные D1 сохраняются в .wrangler/state. В Windows можно запускать Start OpenCalendar.cmd после установки зависимостей и применения миграции.

```sh
pnpm test
pnpm run build
```

Облачная сборка: dist/server/index.js, включающая клиентские файлы. После успешной публикации через Sites приложение и D1 работают независимо от вашего ПК. Сам по себе локальный адрес или успешная сборка не означает публикацию.

Закрытый доступ Sites предназначен для проверки владельцем. Для приглашения других пользователей и работы API из мобильных оболочек необходимо отдельно настроить подходящую аудиторию. Секрет обхода доступа Sites нельзя включать в приложение.

## Мобильные оболочки

```sh
pnpm run build:mobile
pnpm run cap:sync
```

Адрес действующего сервера уже указан в mobile.config.json. Для другого сервера переопределите VITE_API_URL публичным HTTPS-корнем API без /api. Папки android/ и ios/ содержат нативные проекты, собственные иконки и настройки возврата OAuth. Подписанные APK/AAB/IPA ещё не собраны. Для iOS нужен Mac/Xcode, для Android — Java и Android SDK; для магазинов нужны аккаунты разработчика.

## Проверки и ограничения

40 автоматических проверок: даты, время, экспорт, языки, права групп, ответы, сохранение сессий, email/scrypt, OAuth с подписанным тестовым ID-токеном, контактные ссылки и удаление данных. Email-регистрация также проверена в настоящей локальной среде Workers/Wrangler и в интерфейсе телефона.

Изменения других участников обновляются каждые пять секунд. Время встреч хранится как общее местное время: участникам из разных часовых поясов нужно договориться, какой пояс использует группа. Гостевой доступ хранится на устройстве и может быть потерян при выходе или очистке данных.

Подробности: [облачное развёртывание](docs/online-deployment.md), [Telegram и мессенджеры](docs/messenger-auth.md), [публикация в магазинах](docs/native-release.md). Секреты хранятся в серверных настройках, локально — в исключённом из Git .dev.vars; имена параметров перечислены в .dev.vars.example.
